Процесс

Как я работаю с агентами

Это не «включил Cursor и жду». Есть процесс, который я выстроил сам за 5 месяцев, методом набитых шишек.

Сначала план, потом код

Прежде чем агент что-то пишет, я формулирую: что должно получиться, какие данные приходят от клиента (и почему им нельзя верить), что нельзя ломать.

Маленькие задачи

Не «сделай экономику», а «добавь проверку X в этом файле, не трогая остальное». Большие правки агент делает хуже и незаметнее ломает соседний код.

Тесты как ворота

304 теста в проекте. Новый код агента не принимается, пока прогон не зелёный — для меня самого это правило, а не для галочки в портфолио.

Я разбираю, что вышло

После того как агент написал код — я читаю диф, прошу объяснить логику, ищу, где он мог схитрить (заглушка вместо реальной проверки — частый грех агентов).

Код из проекта

Несколько реальных решений — с объяснением своими словами

Взял не все 15 сервисов, а несколько, логику которых могу пересказать и защитить сам, без подсказок. Полный код — на созвоне или по запросу.

01

Клиенту нельзя верить — цену считает сервер

Игрок мог бы вызвать покупку с любыми аргументами через эксплойт. Поэтому от клиента идёт только id апгрейда, а цену, баланс и лимиты сервер пересчитывает сам из своих данных.

server/services/EconomyService.ts 
// от клиента пришёл только upgradeId
const playerData = selectServerPlayerData(state, userId);
if (!playerData) return;
const template = UPGRADES[upgradeId];
if (!template) return;

const purchaseCost = getScaledCost(template.baseCost, template.costMultiplier, upgrade.level);
if (!bnGte(playerData.currency, purchaseCost)) return; // денег не хватает

obbyStore.upgradePurchased(userId, upgradeId, nextLevel, nextCost, purchaseCost);
Своими словами: смысл простой — сервер никогда не доверяет цифрам от игрока, только его намерению («хочу купить X»). Всё, что влияет на баланс, пересчитывается заново на сервере. Это база анти-чит логики, тут я разбираюсь уверенно.
02

Чек за покупку может прийти дважды — награда не должна выдаться дважды

Roblox может прислать один и тот же чек повторно. Если просто выдавать награду при получении чека — получится дублирование кристаллов.

server/services/PurchaseService.ts 
const existing = playerData.processedReceipts[purchaseId];
if (existing !== undefined) {
  // чек уже обработан — просто подтверждаем, ничего не выдаём заново
  return this.dataService.synchronizePlayersNow([userId])
    ? PurchaseGranted : NotProcessedYet;
}

obbyStore.__grantDeveloperProduct(userId, purchaseId, newCrystals, receipt);
return this.dataService.synchronizePlayersNow([userId])
  ? PurchaseGranted : NotProcessedYet;
Своими словами: каждый чек запоминается по id. Если он приходит снова — сервер не выдаёт награду ещё раз, а просто говорит «да, всё ок, уже выдано». Это то, что называется идемпотентностью: одна и та же операция, выполненная N раз, не должна дать разный результат.
03

Межсерверный босс: 10 серверов бьют одновременно

У босса есть revision — номер версии его состояния. Каждый удар проверяет, что бьёт по актуальной версии, а не по устаревшей, которую сервер получил секунду назад.

server/services/ClanService.ts 
runtime.bossMap.UpdateAsync(STATE_KEY, (rawState) => {
  const current = this.decodeBossState(rawState) ?? runtime.boss;
  if (current.isDefeated) return undefined; // уже убит — не трогаем

  const dealt = math.min(current.currentHP, damage);
  return JSONEncode({
    ...current,
    currentHP: current.currentHP - dealt,
    revision: current.revision + 1,
  });
}, STATE_TTL_SECONDS);
Своими словами: босс общий на все сервера, а не свой на каждом. Если бы каждый сервер тупо вычитал урон из своей копии HP — можно было бы дважды посчитать один и тот же удар или, наоборот, потерять урон другого сервера. UpdateAsync гарантирует, что изменение всегда идёт от актуального состояния, а revision — просто счётчик, чтобы было видно, что состояние точно свежее, а не залежавшееся. Могу объяснить логику, но не готов на лету разбирать все тонкости API MemoryStore — это смотрел вместе с агентом при отладке гонки, которая реально была на проде.
