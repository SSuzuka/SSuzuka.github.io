Собираю рабочие игровые системы через AI-агентов — от вопроса до теста

5 месяцев разработки одного проекта на Roblox. Не пишу код руками с нуля — выстраиваю процесс: ставлю задачу агенту → нахожу, где он ошибся или схалтурил → дожимаю до рабочего решения → проверяю тестами. Первая версия от агента почти никогда не финальная — часть работы как раз в том, чтобы это заметить и не пропустить.

Сразу к делу

Что реально умею, а что нет

Пишу прямо, чтобы не тратить время ни себе, ни вам на созвоне.

✓ Умею

  • Спроектировать систему (экономика, профили игрока, межсерверные механики) и провести её через реализацию агентом до рабочего состояния
  • Найти сценарий, который сломает систему: гонки данных, дубли, спам, разрыв соединения в неудобный момент
  • Заметить, что агент сделал заглушку или упростил вместо честного решения, и дожать до нормального фикса
  • Держать процесс на тестах: правило простое — не прошли тесты, значит не готово
  • Объяснить, *как* я довожу задачу до результата (процесс), а не *как устроен* конкретный API изнутри

✕ Пока не умею / не буду

  • Живое кодирование на созвоне под таймером
  • Разбор тонких деталей конкретного API без возможности проверить — честно скажу «не знаю навскидку»
  • Писать много кода руками вообще без ИИ — не изображаю это
  • Показать сразу весь код проекта публично — экономика игры боевая, часть кода трогать открыто не готов
Процесс

Как выглядит моя работа над задачей

Это не «включил Cursor и жду». Условная цепочка, которая почти никогда не проходит с первого раза идеально.

задача
→
вопросы себе / агенту
→
контракт (что нельзя ломать)
→
агент пишет
→
я проверяю руками / сценариями
→
правки
→
тесты / линт

Первая версия — черновик

Агент почти всегда выдаёт что-то рабочее, но не финальное: где-то заглушка, где-то не учтён редкий случай. Это нормальная часть процесса, а не провал.

Моя часть — заметить и дожать

Я тестирую руками (спам кликов, разрыв соединения, повторный запрос) и требую от агента закрыть конкретный найденный случай, а не абстрактно «улучшить».

Тесты — граница готовности

304 теста в проекте. Задача не закрыта, пока прогон не пройден полностью — для меня самого, это не для галочки.

Инструменты меняются быстро

Модели, агентские харнессы, паттерны работы с контекстом обновляются каждые несколько месяцев. Слежу за этим целенаправленно, а не жду, что кто-то расскажет.

Пример

Как это выглядело на реальной задаче

Без вываливания всего кода — только суть ситуации и что я лично сделал в ней.

задача

Перевод игровой валюты между игроками (клан-система).

что нашёл сам

Протестировал руками: быстро кликнул «перевести» несколько раз подряд, вышел из игры сразу после отправки запроса, попробовал открыть перевод на двух вкладках. Первая версия от агента спокойно давала задвоить перевод при быстром повторном клике — деньги списывались дважды.

что сделал

Показал агенту конкретное воспроизведение (не «почини race condition», а «вот шаги, вот результат, вот что должно быть вместо этого»), попросил блокировку повторного запроса и версию с явным подтверждением состояния перевода.

результат (кусок финального кода) 
if (!this.tryLockUser(senderUserId)) {
  // повторный клик того же перевода — не вторая транзакция
  sendTransferResult(player, requestId, sameRequest ? "pending" : "rejected", ...);
  return;
}
