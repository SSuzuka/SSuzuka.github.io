TOCTOU: между «проверил» и «записал» данные могут измениться

Перевод кристаллов трогает два профиля. Между проверкой и записью не должно быть ни одного yield — иначе вклинится конкурентная операция. Проверка без await + запись всех участников одним пакетом.

server/data/DataService.ts 
// проверка: ни одного await/yield внутри
public canSynchronizePlayers(userIds: string[]): boolean {
  for (const userId of userIds) {
    const session = this.activeSessions.get(userId);
    if (!session || session.isReleasingLocally || !session.profile.IsActive()) return false;
  }
  return true;
}

// двухфазный коммит: всем профилям сразу Data, потом всем Save
for (const [session, data] of snapshots) session.profile.Data = data;
for (const [session] of snapshots) session.profile.Save();

Клановый босс: 10 серверов бьют одновременно — кто напишет HP последним?

Решение: босс живёт в MemoryStore, и UpdateAsync сериализует все удары со всех серверов. Оверкилл физически не может открыть следующего босса раньше времени, потому что каждое обновление видит свежее состояние.

server/services/ClanService.ts 
runtime.bossMap.UpdateAsync(STATE_KEY, (rawState) => {
  const current = this.decodeBossState(rawState) ?? runtime.boss;
  const activeBoss = this.expireBoss(current, now); // проверка периода
  if (activeBoss.isDefeated) return undefined;     // уже убит — не трогаем

  const dealt = math.min(activeBoss.currentHP, damage);
  return JSONEncode({
    ...activeBoss,
    currentHP: activeBoss.currentHP - dealt,
    revision: activeBoss.revision + 1,        // каждая запись версионируется
  });
}, STATE_TTL_SECONDS);

После UpdateAsync нельзя слепо писать в DataStore — ретрай продублирует побочный эффект

Сохранение босса в DataStore — идемпотентное: ключ ретрая включает generation и revision, а сама запись пропускается, если в базе уже лежит более свежая версия.

server/services/ClanService.ts 
// ключ ретрая уникален для каждого поколения/ревизии → повтор не дублирует
safeDataStoreCall(`boss-progress:${clanId}:${boss.generation}:${boss.revision}`, () =>
  this.clanStore.UpdateAsync(clanId, (rawRecord) => {
    const stored = record.bossProgress;
    // в базе уже новее — наша запись устарела, выходим без перезаписи
    if (
      stored.generation > boss.generation ||
      (stored.generation === boss.generation && stored.revision > boss.revision)
    ) return record;
    record.bossProgress = { ...boss, revision: boss.revision };
    return record;
  })
);
06

Конфликт версий: старый сервер перезаписывает прогресс, сделанный новым

У босса явные generation (жизненный цикл) и revision (каждая правка). Восстановление после рестарта идёт от большего к меньшему: свежая ревизия побеждает, HP пересчитывается пропорционально конфигу уровня.

server/services/ClanService.ts 
restoreBossFromProgress(progress: StoredClanBossProgress): ClanBossState {
  const configuredMaxHP = getClanBossMaxHP(progress.level);
  // баланс HP: храним % от старого максимума, применяем к новому конфигу
  const currentHP = math.clamp(
    math.floor(progress.currentHP / storedMaxHP * configuredMaxHP + 0.5),
    0, configuredMaxHP
  );
  return {
    level: progress.level,
    currentHP,
    generation: progress.generation,
    revision: progress.revision,
    ...
  };
}

08

Спам по RemoteEvent: дабл-файр, макросы, «убить монстра» 1000 раз в секунду

Rate limit на каждое событие с оглядкой на реальную скорость игры: клики 60/с, покупки 5/с. Превышение — тихое отбрасывание пакета, без кика: кик даёт ложные срабатывания и банит ни в чём не виноватых.

server/middleware/rateLimit.ts 
return (player, ...args) => {
  const currentTime = Workspace.GetServerTimeNow();
  let data = eventTraffic.get(config.eventKey);

  if (!data) { ... processNext(player, ...args); return; }
  if (currentTime - data.lastResetTime >= config.windowSeconds) {
    data.packetCount = 1; data.lastResetTime = currentTime;  // окно истекло
    processNext(player, ...args); return;
  }

  data.packetCount += 1;
  if (data.packetCount > config.maxPackets) return; // тихо дропаем
  processNext(player, ...args);
};

NaN, бесконечность, дробные, отрицательные — что угодно может прийти от клиента

Каждый входящий параметр проходит нормализацию до любых расчётов: NaN, ±Inf, floor, диапазон. Кривой ввод молча отсекается, а не валит расчёт.

server/services/EconomyService.ts 
function normalizeBatchCount(count: number): number | undefined {
  if (count === -1) return -1; // «купить максимум»
  if (count !== count || count === math.huge || count === -math.huge ||
      count < 1 || count % 1 !== 0) return undefined; // NaN/Inf/дробные/0
  if (count > MAX_CLIENT_BATCH_COUNT) return undefined;
  return count;
}

Процесс

Как в это вписаны AI-агенты

Я не «пользуюсь Cursor» — я управляю агентами по правилам, которые сам написал. Это даёт скорость без развала архитектуры.

Контракт до кода

Слои, import-матрица, запреты и паттерны описаны заранее. Агент не может «наулучшать всё» — у него есть рамки.

Задача = юнит

Крупная фича бьётся на изолированные задачи с критериями готовности. Диффы не больше сотен строк.

Тесты — ворота

Код агента проходит те же 304 теста, что и мой. Слово «починил» без зелёного прогона не засчитывается.

Техчасть — за мной

Схема данных, сервер, сеть, UI, сборка. Агенты исполняют план, я отвечаю за архитектуру и результат.
